CS 465 Module Eight Journal

Throughout this course, I developed a full stack web application for Travlr Getaways using Express, MongoDB, Angular, and Node.js. The project included both customer-facing webpages and an administrator single-page application (SPA) used to manage travel packages.

The frontend development evolved throughout the course. Initially, Express and Handlebars were used to create server-rendered HTML pages. This approach generated complete pages on the server before sending them to the browser. JavaScript was then used to add functionality and improve the user experience. Later in the project, Angular was introduced to create a single-page application (SPA) for the administrative interface. Unlike server-rendered pages, the SPA dynamically updates content without requiring full page reloads. This provided a more responsive and interactive experience while reducing communication overhead between the client and server.

MongoDB was selected as the backend database because it is a NoSQL document database that stores data in flexible JSON-like documents. The travel package information did not require complex relational structures, making MongoDB a good choice for the application. MongoDB also integrates well with Node.js through Mongoose, allowing application objects to map directly to database documents and simplifying development.

JSON differs from JavaScript because JSON is a lightweight data-interchange format used to transmit structured data, while JavaScript is a programming language used to implement application logic. JSON served as the communication layer between the Angular frontend and the Express backend. For example, when retrieving trips, the Angular application sent HTTP requests to the REST API, and the server returned trip information in JSON format. The Angular application then used that data to update the user interface dynamically.

Several examples of refactoring occurred during development. Early versions of the project used static data stored locally within the application. Later, the code was refactored to retrieve trip information from MongoDB through REST API endpoints. Additional refactoring occurred when reusable Angular components and services were created for trip management functionality. Reusable UI components improved maintainability, reduced duplicate code, promoted consistency throughout the application, and simplified future enhancements.

Testing played a significant role throughout the project. REST API endpoints were tested using Postman to verify request and response behavior. Methods such as GET, POST, PUT, and DELETE were used to retrieve, create, update, and remove travel package information. Endpoints defined the URLs used to access specific application resources. Security testing was added during the final phase of the project through JWT authentication and Passport. User registration and login endpoints were tested to ensure only authenticated users could access protected administrative functions. Testing both authorized and unauthorized requests helped verify that security controls were functioning correctly.

This course contributed significantly to my professional goals as a future data engineer and software developer. I gained hands-on experience developing a complete full stack application using modern technologies including Angular, Express, Node.js, MongoDB, REST APIs, and JSON Web Tokens. I strengthened my understanding of frontend and backend integration, database design, API development, authentication, and testing methodologies. Most importantly, I learned how the individual components of a full stack application work together to create a functional, secure, and maintainable system. These skills will be valuable in both software development and data engineering roles as I continue building my technical career.
